# ADR-0004: UUIDv7 via DB function + app generator

Status: Accepted (2026-10-28) · Enforces invariant I1

## Context

Spec §2/§4.1: primary keys are UUIDv7 (RFC 9562 time-ordered) for index locality and
chronological debuggability. Postgres `gen_random_uuid()` produces v4 — non-conforming.

## Decision

- App: `packages/domain/src/uuid.ts` — `newUuidv7()` (48-bit ms timestamp + version 7 +
  variant 10 + 74 random bits; monotonic same-millisecond increment of the random-a field so
  IDs generated in one process sort chronologically). Unit-tested for format, version,
  variant, and sort order.
- DB: function `lanxu_uuidv7()` (plpgsql, no extensions: hex-built 48-bit `clock_timestamp()`
  + version bits + `random()` fields) installed in migration `0001`, used as
  `DEFAULT lanxu_uuidv7()` on all business PKs so raw SQL inserts/constraints/seeds also
  comply.
- Cross-process same-ms ordering is best-effort (per RFC); anything needing strict order uses
  explicit `store_seq` / monotonic columns, never ID lexicography alone.

## Consequences

+ Time-ordered PKs (clustered-friendly inserts), no v4 drift from any insert path.
− Two generators to keep in sync semantically → shared test vectors in Phase 01 suite
  (format + version + ordering properties asserted for both).
